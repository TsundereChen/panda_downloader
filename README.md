# Private E-Hentai / ExHentai archive bot

This Telegram bot accepts a gallery URL and saves the archive generated by the
site itself to a configured local folder. It supports both `e-hentai.org` and
`exhentai.org`, requires a logged-in site session, and adds a second bot-login
gate before it will accept downloads.

Use it only with an account and content you are authorized to access, and keep
the bot private. The service never uploads archives to Telegram.

## Setup

1. Create a bot with [@BotFather](https://t.me/BotFather), then copy the token.
2. Install [uv](https://docs.astral.sh/uv/) and synchronize the bot dependencies:

   ```sh
   uv sync
   ```

3. Copy the template and set restrictive permissions:

   ```sh
   cp .env.example .env
   chmod 600 .env
   ```

4. Get the site session cookie with the separate interactive WebView helper.
   It opens a user-controlled browser window; complete the site verification
   and login yourself. It starts at E-Hentai, then automatically opens
   ExHentai after sign-in. When the terminal says `EH_COOKIE` was saved, close
   the window normally. The helper writes only `EH_COOKIE` into the bot
   configuration:

   ```sh
   uv run --extra login eh_web_login.py --write-env .env
   ```

   This is an interactive login, not a challenge bypass. If your desktop
   WebView is also rejected, sign in through your usual browser and paste its
   complete Cookie request header into `EH_COOKIE` manually. Cookies expire;
   rerun the helper or refresh the value when the bot reports an expired
   session.
5. Start the bot once with `ALLOWED_TELEGRAM_USER_IDS` empty, send `/whoami`,
   then set that ID in `.env` and restart it. Set a long `BOT_ACCESS_PASSWORD`.
6. Start it:

   ```sh
   uv run bot.py
   ```

## Docker

Build and start the image with a persistent local download folder:

```sh
docker compose up --build -d
```

The compose file loads the same `.env` values and mounts `./downloads` at
`/downloads` inside the container. To use a different host folder, change the
left side of the volume mapping. The image runs as an unprivileged user and
does not include `.env`.

Run the interactive helper on a desktop host, not in the headless bot
container. The container needs only the `EH_COOKIE` value in its `.env`.

To run without Compose:

```sh
docker build -t eh-telegram-archive .
docker run -d --name eh-telegram-archive --env-file .env \
  -e DOWNLOAD_DIR=/downloads -v "$PWD/downloads:/downloads" \
  --restart unless-stopped eh-telegram-archive
```

## Use

In Telegram, send `/login <BOT_ACCESS_PASSWORD>` in a private chat, then paste
or forward a message containing a canonical gallery URL, for example:

```
https://e-hentai.org/g/123456/abcdef1234/
```

The bot requests an `org` archive by default, waits for the site to prepare it,
and writes the result to `DOWNLOAD_DIR`. Change `ARCHIVE_TYPE=res` to request a
resampled archive instead. `/status` confirms configuration without exposing
any cookie or password.

## Operations and security

- Treat `.env` as a secret: it contains your Telegram token and logged-in site
  session. It is intentionally ignored by Git.
- Use a dedicated service account and restrict `ALLOWED_TELEGRAM_USER_IDS`.
- Bot login is intentionally in-memory; a restart logs every user out.
- Downloads are serialized so multiple Telegram messages do not accidentally
  create overlapping archive jobs or spend account quota unexpectedly.
- `MAX_ARCHIVE_GIB` bounds storage use. Partial files over the limit are removed.
- Run this only on a machine you control. For a persistent service, place it
  behind a system service manager and set an absolute `DOWNLOAD_DIR`.
